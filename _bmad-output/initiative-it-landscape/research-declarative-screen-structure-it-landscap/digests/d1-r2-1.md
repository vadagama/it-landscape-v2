- Homepage supports pinning a whole dashboard (not individual widgets) to the bottom; Ardoq's own best practice is a dedicated home dashboard and using the homepage as "a launch pad, not a destination" — Ardoq Help, 2026-07-21, accessed 2026-10-04 — same URL — confidence high — class: practice
- Dashboard filters are created on the dashboard, render at the top of the dashboard wherever embedded (including homepage), apply with AND logic, work with Advanced Search and most Gremlin reports, support Number/Pie/Bar/Table charts; a viewer's filter selection is temporary and resets on refresh — Ardoq Help, 2026-07-21, accessed 2026-10-04 — same URL — confidence high — class: pattern

- Component Overview page = unified single-component "profile page" with 5 tabs: Overview (read-only summary: name/type/description, Priority Fields, key field values, relationship summary, visual preview), Fields (inline editing via pencil icon; Priority Fields section on top; read-only system fields at bottom; calculated fields read-only with calculator icon), References (see below), Viewpoints (all viewpoints featuring this component; hover to preview; click to open full visualization), Styles (icon from 250+ incl. ### Q5 Cross-tool synthesis (evidenced patterns only)
- Declarative home surfaces exist in at least two of the four tools: Ardoq's admin-configured homepage (cards per component type/workspace + quick actions + pinned dashboard) and Backstage's app-config-driven card/tab placement (round 1); Essential instead declares a portal→section→report taxonomy configured in the repository tool — class: pattern (synthesis of above sources)
- Entity detail pages converge on "tabbed profile + typed-relations area": Ardoq (Overview/Fields/References/Viewpoints/Styles, references grouped by typed triple, hierarchy separate), Backstage (`/catalog/:namespace/:kind/:name` route, per-kind page composition, relations/ownership cards — round 1 + READMEs), Essential (per-class reports; editor-builder lead suggests same declarative anatomy) — class: pattern
- Typed relations are surfaced as first-class grouped lists with click-through to the other endpoint (Ardoq triple groups with clickable Source/Type/Target; Backstage relation cards link to related entities — round 1) — class: pattern
- Navigation: all three read tools pair a global search entry point (Ardoq global search + ⌘K palette; Essential header Document Search; Backstage inline catalog search — round 1) with a hierarchy/tree or curated-taxonomy browse (Ardoq Components Browser tree + Data Inventory; Essential portals/sections; Backstage Groups/ownership sidebar items) — class: pattern
- Drilldown-in-context vs standalone: Ardoq explicitly offers both (drawer from visualization/inventory, standalone page from search) — a pattern directly transferable to a declarative screen structure — class: pattern
- Dashboards for stakeholder demos are a distinct top-level object in both Ardoq (dashboards, shareable, filterable, embeddable on homepage) and Essential (dashboards are reports inside portals, e.g. IT Asset Dashboard, Application Dashboard); Ardoq additionally ships Present mode/presentations (existence evidenced; body unread) — class: pattern
