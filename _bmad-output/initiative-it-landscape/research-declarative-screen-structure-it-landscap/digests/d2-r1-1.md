## Findings

### Q2/Q6 — Ardoq: relation visualization types
- Ardoq's help-center sitemap documents a large view catalog relevant to relations: Dependency Map, Dependency Matrix, Dependency Wheel, Relationships View, Block Diagram, Capability Map, Component Tree, Tables, Treemap, Timeline View (+ separate "Timeline View view style"), Swimlanes, Spider Chart View, Bubble Chart View, Heat Map, Graph Filters, plus "Introducing Scenarios: model alternative futures and analyze the impact of change" (updated 2026-01-06) and "How to create focused views using required paths and collapse paths" (updated 2025-07-09) — Help.ardoq.com sitemap, entries dated 2023-03 to 2026-09, accessed 2026-10-04 — https://help.ardoq.com/sitemap.xml — confidence high — class: doc
- The Dependency Map "shows dependencies between your applications, processes, and other components across or inside workspaces"; the component in context renders at the top, descendant (hierarchy) components have square corners, referenced components have rounded corners — Ardoq Help, "Dependency Map", updated 2026-09-17 (sitemap timestamp; page says "updated over 2 weeks ago"), accessed 2026-10-04 — https://help.ardoq.com/en/articles/44007-dependency-map — confidence high — class: doc
- The Dependency Map traverses references as a graph: multiple degrees of referenced components are configurable via separate incoming-degree and outgoing-degree sliders — same source — confidence high — class: pattern
- Reference chains in the Dependency Map are strictly directional: an incoming chain can contain only incoming references and cannot switch direction mid-chain; mixed-direction 2nd-degree relations are delegated to the Block Diagram view — same source — confidence high — class: pattern (a documented modeling limit of the view)
- Documented behavioral limit: "Ardoq only loads components which are directly referenced from a loaded workspace" — multi-degree traversal silently misses branches whose workspaces are not open; loading multiple workspaces produces a more detailed map — same source — confidence high — class: failure
- View settings evidenced: "Show Only Connected Components" (omit components without references), "Show Vertical / Show Horizontal" (root-node layout), "Color by Reference Type" (color referenced nodes by reference-style line color), "Include Reference Parents" slider (parents shown with dotted border; common ancestors merged), "Collapse Groups / Collapse Component Hierarchy" depth slider producing a summary view — same source — confidence high — class: pattern
- Perspectives = saved view configuration: conditional formatting and reference-labeling (e.g., show reference type as label on each referenced component) tell the map "a story"; default grouping is "Group by Parent All", other grouping rules include grouping referenced components by Component Type — same source — confidence high — class: pattern
- Drilldown/interaction: hovering highlights all visible instances of the component; left-click navigates to the component (opening its workspace if needed); right-click opens the component context menu; view exports to PNG or into an Ardoq Presentation — same source — confidence high — class: pattern
- Deterministic reference sorting: by direction (incoming first, outgoing second), then reference type, then navigator sort, then alphabetically — same source — confidence high — class: doc
- Block Diagram "graph traversal" config: a top-bar dropdown sets total degrees of relationships plus advanced separate incoming/outgoing degrees; traversal stops on paths violating the chosen direction; with zero degrees only the selected component shows and the rest of the graph is faded out — Ardoq Help, "Graph Traversal", 2025-07-07, accessed 2026-10-04 — https://help.ardoq.com/en/articles/44056-graph-traversal — confidence high — class: pattern
- Traversal can be restricted to selected reference types, grouped by incoming vs outgoing types (including parent/child-as-reference options); the Dependency Map exposes an interactive visual simulation of traversal semantics (two sliders) behind an info icon in the degrees dropdown — both articles above — confidence high — class: pattern

### Q3 — Backstage plugin-catalog-graph
- @backstage/plugin-catalog-graph v0.6.9-next.0 (license Apache-2.0) has NO third-party graph-visualization dependency: runtime deps are only @backstage/* workspace packages, @material-ui/core|icons|lab, @remixicon/react, classnames, lodash, qs, react-use, zod — Backstage monorepo package.json (master), accessed 2026-10-04 — https://raw.githubusercontent.com/backstage/backstage/master/plugins/catalog-graph/package.json — confidence high — class: version
- @backstage/core-components v0.18.15-next.1 (Apache-2.0) depends on @dagrejs/dagre ^1.1.4, d3-selection ^3.0.0, d3-shape ^3.0.0, d3-zoom ^3.0.0 (plus @material-table/core, react-window, etc.) — Backstage monorepo package.json (master), accessed 2026-10-04 — https://raw.githubusercontent.com/backstage/backstage/master/packages/core-components/package.json — confidence high — class: version
- Inference (manifest-level, source file not yet read): the catalog graph therefore renders through core-components' graph component — bespoke SVG with dagre for layout and d3-zoom/d3-selection/d3-shape for rendering/pan-zoom — and NOT Cytoscape.js, Sigma.js, react-force-graph, vis-network, or React Flow — derived from the two package.jsons above — confidence medium-high — class: version (verify: packages/core-components/src/components/DependencyGraph)
- Plugin surface: `EntityCatalogGraphCard` — "a card that displays the directly related entities to the current entity", placed on the entity page, customizable with "filtering for specific relations"; `CatalogGraphPage` — standalone viewer "to navigate through the entities and filter for specific relations", supports initial state (e.g., `selectedKinds: ['component','domain','system','api','group']`); `EntityRelationsGraph` — reusable component to build custom relation graphs — plugin README (master), n.d., accessed 2026-10-04 — https://raw.githubusercontent.com/backstage/backstage/master/plugins/catalog-graph/README.md — confidence high — class: doc
- Relation-type model is pluggable per installation: `DefaultCatalogGraphApi` takes `knownRelations: [...ALL_RELATIONS, 'myRelationOf', ...]`, directional `knownRelationPairs: [...ALL_RELATION_PAIRS, ['myRelationOf','myRelationFor']]`, and `defaultRelationTypes: { exclude: [...] }` (custom relations can be hidden from default selection) — same README — confidence high — class: doc
- Node rendering and drilldown: nodes are custom SVG (`<g onClick>` with `<rect>`/`<text>`, clickable class) via a `renderNode` prop; clicking a node navigates to the catalog entity page (external route binding `catalogEntity → catalogPlugin.routes.catalogEntity`); URL/query state handled via `qs` — same README + package.json — confidence high — class: pattern

### Q6 — Impact-analysis UX patterns (synthesis of retrieved evidence)
- Depth and direction are first-class, user-facing controls: separate incoming/outgoing degree sliders (Ardoq Dependency Map and Block Diagram traversal) — pattern, see Q2 bullets — confidence high — class: pattern
- Relation-type filtering at traversal time, grouped by direction (Ardoq reference-type selection); in Backstage, relation types are selectable filter chips with safe defaults via `defaultRelationTypes.exclude` — confidence high — class: pattern
- Progressive disclosure instead of full-graph dump: untraversed graph faded out, collapse-hierarchy depth slider, "show only connected components", "required/collapse paths" viewpoint options (Ardoq, per sitemap) — confidence high — class: pattern
- Drilldown = navigation, not modal detail: click a node → entity page / opens workspace; hover = highlight all instances (Ardoq); Backstage node click → catalog entity route — confidence high — class: pattern
- Both retrieved tools implement impact analysis as interactive graph exploration; no precomputed "impact list" UI was found in any fetched source — confidence high (as a gap) — class: failure
- No documented node-count/performance limits for interactive graphs were found in retrieved sources; the only documented scalability constraint is Ardoq's workspace-loading rule (only directly-referenced components of loaded workspaces are traversed) — confidence high (as a gap) — class: failure
