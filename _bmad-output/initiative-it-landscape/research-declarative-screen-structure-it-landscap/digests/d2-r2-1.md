**Backstage DependencyGraph core (source-verified, primary)**

- `DependencyGraph.tsx` is only a lazy-loading wrapper (`React.lazy` + Suspense) re-exporting props from `DependencyGraphContent.tsx`; all logic lives in the content file — Backstage repo, accessed 2026-10-04 — https://raw.githubusercontent.com/backstage/backstage/master/packages/core-components/src/components/DependencyGraph/DependencyGraph.tsx — high — doc
- Layout is `@dagrejs/dagre` (`dagre.layout(graph)`); interaction is d3-zoom + d3-selection; fullscreen via `react-full-screen`; rendering is a single SVG with a `<g id="workspace">` transform — Backstage, accessed 2026-10-04 — https://raw.githubusercontent.com/backstage/backstage/master/packages/core-components/src/components/DependencyGraph/DependencyGraphContent.tsx — high — pattern
- Zoom is d3.zoom with `scaleExtent([1, Infinity])` → zoom-in only (cannot zoom out below 100%); pan is clamped to the graph's bounding box; zoom modes `enabled | disabled | enable-on-click` (default enabled) — Backstage, accessed 2026-10-04 — same URL — high — pattern
- Layout-config surface (all public props): `direction` default `TOP_BOTTOM` (maps to dagre `rankdir`; other values per `Types.Direction`), `align`, `nodeMargin` 50, `edgeMargin` 10, `rankMargin` 50, `paddingX/Y` 0, `acyclicer` optional `'greedy'`, `ranker` default `NETWORK_SIMPLEX`, `labelPosition` default RIGHT, `labelOffset`, `edgeRanks` (dagre minlen, default 1), `edgeWeight`, `fit` `'grow' | 'contain'`, `curve` `'curveMonotoneX' | 'curveStepBefore'`, `showArrowHeads` default **false**, `allowFullscreen` default true — Backstage, accessed 2026-10-04 — same URL — high — doc
- Custom rendering hooks `renderNode`, `renderEdge`, `renderLabel` (React component factories over dagre node/edge data); nodes measured via getBBox with a settle-after-2-measured-layouts loop and a 500 ms fallback — Backstage, accessed 2026-10-04 — same URL — high — pattern
- No node-count / graph-size limit of any kind appears in the component code (only debounce 250 ms leading re-layout); absence is in code, not a documented guarantee — Backstage, accessed 2026-10-04 — same URL — high — pattern
- Click-to-highlight, hover-highlight and direction toggle are NOT implemented in the core component; its interaction surface is zoom/pan/fullscreen only (+ whatever `renderNode` attaches as onClick) — Backstage, accessed 2026-10-04 — same URL — high — pattern

**Backstage catalog-graph plugin (source-verified, primary)**

- `CatalogGraphPage` renders a toggleable filter sidebar with exactly these controls: `MaxDepthFilter`, `SelectedKindsFilter`, `SelectedRelationsFilter`, `DirectionFilter`, `CurveFilter`, `SwitchFilter` unidirectional ("simplified"), `SwitchFilter` mergeRelations — Backstage, accessed 2026-10-04 — https://raw.githubusercontent.com/backstage/backstage/master/plugins/catalog-graph/src/components/CatalogGraphPage/CatalogGraphPage.tsx — high — pattern
- Drilldown pattern: clicking a node **re-roots the graph** on that node (`setRootEntityNames([nodeEntityName])`); shift+click navigates to the entity page; both instrumented via analytics — Backstage, accessed 2026-10-04 — same URL — high — pattern
- Page `initialState` is a typed declarative config: `selectedRelations`, `selectedKinds`, `rootEntityRefs`, `maxDepth`, `unidirectional`, `mergeRelations`, `direction`, `showFilters`, `curve` — Backstage, accessed 2026-10-04 — same URL — high — pattern
- Plugin ships three surfaces: `EntityCatalogGraphCard` (entity-page card, customizable relation filter), `CatalogGraphPage` (standalone viewer with filtering/navigation), `EntityRelationsGraph` (headless component for custom graphs); custom relation types registered via `DefaultCatalogGraphApi` with `knownRelations`, `knownRelationPairs`, `defaultRelationTypes: { exclude | include }` — Backstage plugin README, accessed 2026-10-04 — https://raw.githubusercontent.com/backstage/backstage/master/plugins/catalog-graph/README.md — high — doc
