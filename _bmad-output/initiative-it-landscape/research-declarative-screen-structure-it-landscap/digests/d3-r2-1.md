### Ardoq — how a roadmap is built
- Roadmaps are built with **Scenarios**: one scenario per project phase (worked example: Skype-for-Business→Teams retirement with Integration / Migration / Retirement phases); a scenario is a **temporary branch off the current state**, so planned changes never touch mainline data — Ardoq Help (Kristine Marhilevica), updated ≈2026-09 ("over 2 weeks ago"), accessed 2026-10-04 — https://help.ardoq.com/en/articles/43997 — high — doc
- Inside a scenario roadmap you create a **Project component** + **Project Phase components**, connect each phase to the systems it impacts, and **populate proposed start/end dates per phase**; the timeline then shows systems impacted per phase, phase start/stop, and milestones — same source, accessed 2026-10-04 — https://help.ardoq.com/en/articles/43997 — high — pattern
- **Scenarios support Block Diagram and Pages view styles only** — no native scenario-timeline rendering; phase visuals are composed manually per phase — same source, accessed 2026-10-04 — https://help.ardoq.com/en/articles/43997 — high — doc (limitation)
- Governance hook: you can add a custom **"Application Roadmap URL" field on the Application component type** (holding a presentation link) and a **dashboard widget listing applications missing roadmaps** — same source, accessed 2026-10-04 — https://help.ardoq.com/en/articles/43997 — high — pattern
- **Quarter-based roadmap is a workaround, not a feature**: a Calculated List Field ("Quarter-Year", values like "Q1 2020") is populated by a Gremlin query deriving quarter+year from `live_end_date`, then displayed as a column in Component Matrix view and shared via Presentation — Ardoq Help, 2023-05-16, accessed 2026-10-04 — https://help.ardoq.com/en/articles/43893 — high — pattern (dated 2023; still the documented method)

### Ardoq — Timeline View rendering & interaction
- Timeline View labels: **multiple labels per component row** selectable from default and custom fields, per-component-type show/hide of field names, order configurable; labels >2 lines truncated with **hover tooltip** showing full value; dividers separate labels; formatting saved inside Viewpoints — Ardoq Help (Urte Berggren), 2026-06-16, accessed 2026-10-04 — https://help.ardoq.com/en/articles/283837 — high — doc
- Timeline hierarchy & interaction: components with **multiple labels or phases** get ^/v expand/collapse; **child components in a hierarchy use +/− icons; groups collapsible**; hover highlights the component **and its timeline row**; **hovering a phase or milestone shows a tooltip**; click applies a **sticky highlight** toggled by clicking again — same source, accessed 2026-10-04 — https://help.ardoq.com/en/articles/283837 — high — pattern

### Ardoq — presentations / demo mode
- Presentations embed **live views and dashboards as slides** — always current with workspace data; update flow is "replace slide with current view"; slide-level rich-text descriptions; slides copyable between presentations — Ardoq Help, 2026-02-18, accessed 2026-10-04 — https://help.ardoq.com/en/articles/44181 — high — doc
- Presentation sharing: play button generates a **shareable link, linkable/embeddable externally** (e.g., SharePoint); read access = Creator / viewer's permissions / entire organization / **anyone with the URL** (public mode must be enabled by Ardoq support) — same source — high — pattern
- **Explore mode** (demo interactivity): double-clicking a component in a slide dynamically re-contextualizes the view to that component; can be turned off per presentation or disabled org-wide via permissions; core viewpoints unsupported — same source — high — pattern
- Slide data scope gotcha: slides only show components from **workspaces that were open when the slide was created**; keyboard navigation shortcuts (Space/arrows/L legend/D description/E explore/F fullscreen) — same source — high — doc

### Ardoq — lifecycle phases on the timeline
- Standardized lifecycle field set recommended across all components/references; minimum = **"Lifecycle Phase" list field (ordered: Implementing → Live → Phasing Out → Retired) + "Live" date range**; optional date-range fields: **Evaluation, Development, Live, Mainstream** (Mainstream = sub-phase of Live) — Ardoq Help (Jon Scott), 2026-07-13, accessed 2026-10-04 — https://help.ardoq.com/en/articles/44045 — high — pattern
- Each lifecycle phase is a **date range with start+end that visualizes in the Timeline View**; end of one phase ideally matches start of the next, **but gaps are allowed** — same source — high — pattern
- Ardoq Application Lifecycle Management is no longer a standalone solution: folded into **Ardoq Foundation as of 2025-09-11**; advanced lifecycle fields remain addable to Foundation Application components — same source — high — doc

### Timeline UX synthesis (evidence-based, for the declarative screen design)
- **Two distinct "roadmap" archetypes** coexist in the evidence: (a) time-based **swimlane timeline** (Ardoq: rows = components grouped by reference hierarchy, horizontal bars = date-range phases, diamonds = milestone dates, quarter axis as a derived-list workaround); (b) **status-column board** (Backstage plugin: items move Suggested→Planned→In Progress→Completed with votes/comments, no time axis). An EA roadmap screen and a community feedback board are different products sharing one word — synthesis of the above sources — high — pattern
- **Phase data model pattern (Ardoq)**: one ordered enum list field ("phase") + one date-range field per phase, on the same entity; timeline renders each date-range as a bar; enum positions the phase; gaps allowed. Roadmap items are children of a project/initiative connected to impacted systems — help.ardoq.com 44045 + 43997 — high — pattern
- **Milestones**: point-in-time date fields render as diamond markers with hover tooltips on the timeline (Ardoq Timeline; round-1 finding reinforced by 283837 hover/tooltip behavior) — help.ardoq.com 283837 — high — pattern
- **Quarterly grids are not native** in either tool studied: Ardoq derives quarter labels via query into a matrix column (2023 workaround); Backstage ecosystem has zero quarterly-planning plugins (count 0) — help.ardoq.com 43893 + GitHub API — high — pattern/number
- **Linking timeline items to entity pages**: Backstage uses URL deep links (`/roadmap?feature=<id>` → detail drawer); Ardoq keeps the row bound to the component in the graph view (hover highlight, sticky click highlight) and re-contextualizes whole slides in presentation Explore mode; LeanIX renders lifecycle state display inside the fact sheet sidebar — raw.githubusercontent + help.ardoq.com 283837/44181 + Wayback LeanIX — high — pattern
- **Demo/presentation layer**: Ardoq's demo mode is a presentation shell over always-live views (not screenshots) with access rights down to "anyone with URL", embeddability, and explore-mode drill-down — a view-adjacent screen type worth considering for an EA catalog product — help.ardoq.com 44181 — high — pattern
