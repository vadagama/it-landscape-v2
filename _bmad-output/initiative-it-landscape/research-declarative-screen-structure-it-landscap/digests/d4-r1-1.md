## Findings

### Q1 — ThoughtWorks Technology Radar format
- The radar is divided into four quadrants — Techniques, Platforms, Tools, Languages & Frameworks — and the individual items plotted on it are called "blips". — ThoughtWorks, n.d., accessed 2026-10-04 — https://www.thoughtworks.com/radar/faq — confidence high — class: doc
- The current ring set is Adopt, Trial, Assess, Caution; the fourth ring was renamed from "Hold" to "Caution" in a recent release (build-your-own-radar release notes state the rename; the FAQ already uses Caution). Note: "Hold" is still the widely copied ring name in third-party tools (see Backstage sample data, Q3). — ThoughtWorks (build-your-own-radar README), n.d., accessed 2026-10-04 — https://raw.githubusercontent.com/thoughtworks/build-your-own-radar/master/README.md — confidence high — class: doc
- Movement/persistence semantics: a blip that does not change rings between editions drops off the next radar edition — the radar carries only blips whose ring changed. — ThoughtWorks, n.d., accessed 2026-10-04 — https://www.thoughtworks.com/radar/faq — confidence high — class: doc
- Radial position within a ring is meaningful: a blip sitting close to the boundary with the next-inner ring signals growing confidence in that direction (e.g., a Trial blip near the Adopt boundary reads as approaching adoption). — ThoughtWorks, n.d., accessed 2026-10-04 — https://www.thoughtworks.com/radar/faq — confidence high — class: doc
- Per-blip movement can be tracked with an optional status column with values New / Moved In / Moved Out / No Change. — ThoughtWorks (build-your-own-radar README), n.d., accessed 2026-10-04 — https://raw.githubusercontent.com/thoughtworks/build-your-own-radar/master/README.md — confidence high — class: doc
- Publication/rendering: the TW radar is produced by its Technology Advisory Board (TAB) and published twice a year as an interactive website (explore, search, deep-link to blips) plus a PDF. — ThoughtWorks, n.d., accessed 2026-10-04 — https://www.thoughtworks.com/radar/faq — confidence high — class: doc
- Official open-source generator "build-your-own-radar" (AGPL) renders a TW-style radar from a Google Sheet, CSV, or JSON with fields name, ring, quadrant, isNew, description; distributed as Docker image `wwwthoughtworks/build-your-own-radar`; ring and quadrant names can be overridden via environment variables. — ThoughtWorks (build-your-own-radar README), n.d., accessed 2026-10-04 — https://raw.githubusercontent.com/thoughtworks/build-your-own-radar/master/README.md — confidence high — class: version

### Q3 — Backstage Tech Radar plugin
- The tech-radar plugin has been moved out of the backstage/backstage monorepo into the backstage/community-plugins repository; it now lives as a workspace at `workspaces/tech-radar` shipping three packages: a frontend plugin, a backend plugin, and a shared `common` package. — Backstage (community-plugins workspace README), n.d., accessed 2026-10-04 — https://github.com/backstage/community-plugins/tree/main/workspaces/tech-radar — confidence high — class: version
- Provenance stated in the plugin README: the radar is inspired by Zalando's Tech Radar (github.com/zalando/tech-radar) and used at Spotify. — Backstage (tech-radar frontend plugin README), n.d., accessed 2026-10-04 — https://github.com/backstage/community-plugins/tree/main/workspaces/tech-radar/plugins/tech-radar — confidence high — class: doc
- Frontend data model: a radar has `title`, `quadrants[]` (id, name), `rings[]` (id, name, color, description), and `entries[]` (id, title, description, key, url, quadrant, timeline[]). — Backstage (tech-radar frontend plugin README), n.d., accessed 2026-10-04 — https://github.com/backstage/community-plugins/tree/main/workspaces/tech-radar/plugins/tech-radar — confidence high — class: doc
- Per-entry history is part of the data model: `timeline[]` points of `moved` ∈ {-1 (moved out), 0 (stayed), 1 (moved in)}, `ringId`, `date` (YYYY-MM-dd), `description` — i.e., ring movement across dated entries drives the displayed history. — Backstage (tech-radar frontend plugin README), n.d., accessed 2026-10-04 — https://github.com/backstage/community-plugins/tree/main/workspaces/tech-radar/plugins/tech-radar — confidence high — class: doc
- Each entry has a `url` field pointing to an internal or external page with more detail — this is the plugin's per-entry detail/link mechanism (the radar itself renders summary info; the detail page lives outside the radar). — Backstage (tech-radar frontend plugin README), n.d., accessed 2026-10-04 — https://github.com/backstage/community-plugins/tree/main/workspaces/tech-radar/plugins/tech-radar — confidence high — class: pattern
- Bundled sample data uses rings adopt / trial / assess / hold with explicit hex colors per ring — i.e., Backstage's sample still uses the old "hold" ring name, not TW's new "Caution". — Backstage (tech-radar frontend plugin README), n.d., accessed 2026-10-04 — https://github.com/backstage/community-plugins/tree/main/workspaces/tech-radar/plugins/tech-radar — confidence high — class: pattern
- Default data supply: the backend plugin fetches a JSON file over HTTP; configured via `techRadar: url:` in app-config.yaml; retrieval goes through the Backstage URL Reader, so JSON living in a (private) git repository works via configured repo integrations. — Backstage (tech-radar-backend plugin README), n.d., accessed 2026-10-04 — https://github.com/backstage/community-plugins/tree/main/workspaces/tech-radar/plugins/tech-radar-backend — confidence high — class: doc
- Custom data supply: implement the `TechRadarApi` interface and bind it to `techRadarApiRef` in the app's ApiFactory to serve radar data from any source; multiple radars are supported by passing an `id` prop. — Backstage (tech-radar frontend plugin README), n.d., accessed 2026-10-04 — https://github.com/backstage/community-plugins/tree/main/workspaces/tech-radar/plugins/tech-radar — confidence high — class: doc
- Maintenance status: the move to community-plugins is confirmed by the workspace README; commit/release activity in 2026 could NOT be verified this run (api.github.com rate-limited for anonymous fetch), so no freshness claim is made. — Run observation, 2026-10-04 — https://api.github.com — confidence high (that verification failed) — class: failure

### Q5 — Patterns linking radar entries to inventory
- The only per-entry outbound-link mechanism evidenced in fetched material is Backstage's entry `url` field (any internal or external page) — the READMEs fetched describe no built-in integration linking radar entries to Backstage catalog entities. — Backstage (tech-radar frontend plugin README), n.d., accessed 2026-10-04 — https://github.com/backstage/community-plugins/tree/main/workspaces/tech-radar/plugins/tech-radar — confidence high — class: doc
- TW's public radar supports search and deep links to individual blips (per the FAQ), but nothing in the fetched material links blips to an application inventory. — ThoughtWorks, n.d., accessed 2026-10-04 — https://www.thoughtworks.com/radar/faq — confidence high — class: doc
- Practical data pattern observed in both ecosystems: radar content lives as a versioned data file decoupled from the UI (Backstage: JSON in a git repo fetched via URL Reader; TW build-your-own-radar: Google Sheet / CSV / JSON). — synthesis of sources in Q1/Q3 — accessed 2026-10-04 — https://raw.githubusercontent.com/thoughtworks/build-your-own-radar/master/README.md — confidence medium (synthesis of two fetched sources) — class: pattern
- Analysis (not a sourced fact): none of the tools reviewed evidences computing "the applications/products that use this technology" from an inventory relation (e.g., a runs-on relation) and surfacing it on the radar entry. Where "linked to products" is wanted, the plausible extension points in evidenced architectures are (a) the per-entry `url` field pointing at an inventory query page, or (b) a custom API implementation (Backstage `TechRadarApi`) that joins radar entries with inventory relations at read time. — Run analysis of retrieved sources — accessed 2026-10-04 — https://github.com/backstage/community-plugins/tree/main/workspaces/tech-radar/plugins/tech-radar — confidence medium — class: pattern

### Q6 — Ring/quadrant semantics and display details
- Ring count and names are data-driven, not fixed: build-your-own-radar defaults to 4 rings (Adopt/Trial/Assess/Caution per the rename note) but allows overriding ring and quadrant names via environment variables; Backstage models rings as an arbitrary `rings[]` array with id, name, color, and description. — ThoughtWorks (BYOR README) and Backstage (frontend README), n.d., accessed 2026-10-04 — https://raw.githubusercontent.com/thoughtworks/build-your-own-radar/master/README.md — confidence high — class: doc
- Movement display conventions: TW/BYOR tracks a per-blip status of New / Moved In / Moved Out / No Change; Backstage encodes per-timeline-point movement as -1 / 0 / 1 with an explicit date. — ThoughtWorks (BYOR README), Backstage (frontend README), n.d., accessed 2026-10-04 — https://github.com/backstage/community-plugins/tree/main/workspaces/tech-radar/plugins/tech-radar — confidence high — class: doc
- History display: Backstage attaches a dated timeline to each entry (ringId + date + description per point), so ring movement over time is first-class data; TW's radar expresses history through ring changes between semi-annual editions (blips that don't move disappear; radial position signals in-ring drift). — ThoughtWorks FAQ and Backstage frontend README, n.d., accessed 2026-10-04 — https://www.thoughtworks.com/radar/faq — confidence high — class: doc
- Per-entry detail pages: TW renders blip pages on the radar site (deep-linkable, per FAQ); Backstage delegates entry detail to the entry's `url` (internal or external page); ring visuals carry explicit colors (Backstage sample uses hex colors per ring). — ThoughtWorks FAQ, Backstage frontend README, n.d., accessed 2026-10-04 — https://github.com/backstage/community-plugins/tree/main/workspaces/tech-radar/plugins/tech-radar — confidence high — class: pattern
