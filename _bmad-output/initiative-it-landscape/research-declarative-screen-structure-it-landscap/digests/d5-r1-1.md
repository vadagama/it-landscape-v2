# D5 r1 — ADR/HLD/RFC documents (assistant 1, round 1)

Method note: tool calls 15/15, distinct sources 9. All claims trace to sources fetched during this run (accessed 2026-10-04); training knowledge was used only to form queries. Failed fetches (unauthenticated api.github.com → 403; madr.github.io → 404; github.com/thombergs/log4brains → 404; npmjs.com → 403 Cloudflare) are not counted as sources. GitHub HTML pages render commit-date columns empty without JS, so repo maintenance recency is largely unverified this run.

## Questions

1. Backstage TechDocs: docs-as-code model (markdown in repo, mkdocs build), how docs attach to catalog entities (tab on entity page), discovery, search over docs, adoption reality.
2. Backstage ADR plugin: how ADRs are discovered (annotations pointing to repo/file patterns), rendered on entity page, MADR support, maintenance status.
3. ADR tooling landscape: MADR template, adr-tools, log4brains — storage formats, published sites, how ADRs link to systems/projects; status conventions.
4. RFC practices in engineering orgs: RFC as artifact type, how RFCs link to systems/products; OSS tools for RFC management.
5. HLD/LLD design documents in enterprises: typical content, where they live, how EA tools or dev platforms link them to systems.
6. Pattern: docs-as-code vs wiki; annotations for linking docs to catalog entities; store documents vs link out.

### Q2 — Backstage ADR plugin

- Plugin packages are now `@backstage-community/plugin-adr` (frontend) and `@backstage-community/plugin-adr-backend` in the backstage/community-plugins monorepo (`workspaces/adr`); the old `@backstage/plugin-adr` was renamed to the community scope; the workspace also contains `adr-common` and `search-backend-module-adr` — GitHub (backstage/community-plugins, workspaces/adr READMEs, main branch), n.d., accessed 2026-10-04 — https://github.com/backstage/community-plugins — high — class: version
- Rendering: ADRs appear as a guarded entity tab: `<EntityLayout.Route if={isAdrAvailable} path="/adrs" title="ADRs"><EntityAdrContent /></EntityLayout.Route>` — the tab renders only when the annotation resolves — GitHub (backstage/community-plugins, adr README), n.d., accessed 2026-10-04 — https://github.com/backstage/community-plugins — high — class: pattern
- Discovery: entity annotation `backstage.io/adr-location: <RELATIVE_PATH_TO_ADR_FILES_DIR>` — path relative to `catalog-info.yaml`, or an absolute URL to the ADR markdown directory; documented example is `docs/adrs` with files `0001-use-adrs.md`, `0002-use-cloud.md` — GitHub (backstage/community-plugins, adr README), n.d., accessed 2026-10-04 — https://github.com/backstage/community-plugins — high — class: pattern
- Search: the backend ships `DefaultAdrCollatorFactory`; ADR search results are typed `adr` and rendered via `AdrSearchResultListItem` (`AdrDocument` from `adr-common`); the plugin enables teams to "discover ADRs across other entities using Backstage Search" — GitHub (backstage/community-plugins, adr-backend README), n.d., accessed 2026-10-04 — https://github.com/backstage/community-plugins — high — class: pattern
- MADR support: the parser handles MADR v2.x and MADR v3.0.0 templates; YAML front matter is recognized only in MADR 3.x files (`---`-delimited) — GitHub (backstage/community-plugins, adr README), n.d., accessed 2026-10-04 — https://github.com/backstage/community-plugins — high — class: version
- Customization: `filePathFilterFn` selects which files count as ADRs (example regex `/^(decided-adrs\/)?\d{4}-.+\.md$/`); content decorators (`createRewriteRelativeLinksDecorator`, `createRewriteRelativeEmbedsDecorator`, `createFrontMatterFormatterDecorator`) fix relative links/embeds and format front matter; backend parser replaceable via `adrExtensionPoint.setAdrInfoParser` returning `{title, status, date}` — GitHub (backstage/community-plugins, adr READMEs), n.d., accessed 2026-10-04 — https://github.com/backstage/community-plugins — high — class: pattern
- Backend reads ADR markdown through configured UrlReaders/integrations config with caching; supports the new backend/frontend systems (extension points `entity-content:adr/entity`, `search-result-list-item:adr`, `api:adr/adr-api`) — GitHub (backstage/community-plugins, adr-backend README), n.d., accessed 2026-10-04 — https://github.com/backstage/community-plugins — high — class: pattern
- Status vocabulary in the plugin's status-component example: draft, proposed, pending, accepted, approved, rejected, deprecated, superseded — GitHub (backstage/community-plugins, adr README), n.d., accessed 2026-10-04 — https://github.com/backstage/community-plugins — high — class: practice

### Q4 — RFC practices

- Rust RFCs: an RFC is a Markdown file merged into the RFC repo; authors copy `0000-template.md` to `text/0000-my-feature.md`; the RFC number is the PR number and each file carries an "RFC PR" link at the top — Rust RFCs README (rust-lang/rfcs), n.d., accessed 2026-10-04 — https://github.com/rust-lang/rfcs — high — class: practice
- Rust RFC decision flow: a relevant sub-team enters Final Comment Period (FCP) lasting 10 calendar days with a disposition (merge/close/postpone); an accepted RFC becomes "active"; the rendered RFC Book lives at rust-lang.github.io/rfcs and active proposals are tracked at rfcbot.rs — Rust RFCs README, n.d., accessed 2026-10-04 — https://github.com/rust-lang/rfcs — high — class: practice
- RFC-to-system linkage (Rust): "Every accepted RFC has an associated issue tracking its implementation in the Rust repository" (priority managed via triage); substantial follow-up changes require a new RFC that notes the original; "postponed" is a standing label — Rust RFCs README, n.d., accessed 2026-10-04 — https://github.com/rust-lang/rfcs — high — class: practice
- Industry naming variants (comment-thread signal, not primary documentation): Uber previously used "RFCs", now "ERDs (Engineering Review Docs)"; Glovo runs the same process as "Request For Comments" — Industrial Empathy blog comments, post dated 2020-07-06, accessed 2026-10-04 — https://industrialempathy.com/posts/design-docs-at-google/ — low — class: practice
- Python PEP 1 (the canonical RFC-like process document) was not fetched within budget — see Leads.

- Typical design-doc sections: Context and scope; Goals and non-goals; Actual design (system-context diagram, APIs, data storage); Alternatives considered; Cross-cutting concerns — Google requires a dedicated privacy design doc when user data is involved — Industrial Empathy, 2020-07-06, accessed 2026-10-04 — https://industrialempathy.com/posts/design-docs-at-google/ — high — class: practice (same 2020 flag)

### Q6 — Pattern: docs-as-code vs wiki; store vs link out

- The linking mechanism in the surveyed portal is a catalog annotation in the entity descriptor: `backstage.io/techdocs-ref: dir:.` (TechDocs) and `backstage.io/adr-location: docs/adrs` (ADR plugin); the portal resolves the annotation and renders or fetches content at read time — Backstage official docs + GitHub (backstage/community-plugins), n.d., accessed 2026-10-04 — https://backstage.io/docs/features/techdocs/creating-and-publishing/ and https://github.com/backstage/community-plugins — high — class: pattern
- Authoring lives in git in every surveyed system: TechDocs Markdown sits next to code; MADR instructs copying templates into `docs/decisions` as `nnnn-title.md`; adr-tools writes Markdown under `doc/adr`; Rust RFCs are Markdown merged into a repo — Backstage docs; adr/madr; npryce/adr-tools; rust-lang/rfcs, n.d., accessed 2026-10-04 — URLs as cited in Q1–Q4 — high — class: practice
- The catalog does not store authored documents: TechDocs stores only generated static sites (local FS / GCS / S3 / Azure / Swift) while source-of-truth Markdown stays in the code repo; docs-not-with-code is supported but still external (annotation `url:` value, standalone `spec.type: documentation` entities) — Backstage official docs, n.d., accessed 2026-10-04 — https://backstage.io/docs/features/techdocs/creating-and-publishing/ — high — class: pattern
- Architectural pattern evidenced across references: the catalog acts as index/renderer/linker (annotation → read-time fetch → entity tab + typed search collator), never as the document store of record — synthesis from the Q1–Q4 sources, each individually cited above — high — class: pattern
- No fetched source directly compares docs-as-code vs wiki for architecture artifacts; the only wiki-adjacent data point is Google keeping design docs in Google Docs (2020 source, stale) — see Not found.
