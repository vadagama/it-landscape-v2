### Q6 — PostgreSQL FTS implementation reality

- Full-text search without an index works but is documented as "too slow" for most applications except ad-hoc queries — PostgreSQL (current docs, PG 18), n.d., accessed 2026-10-04 — https://www.postgresql.org/docs/current/textsearch-tables.html — confidence high — class: doc
- Expression index pattern: `GIN (to_tsvector('english', body))`; only the two-argument, config-specified `to_tsvector` is allowed in an expression index (must be config-independent) — PostgreSQL (current docs), n.d., accessed 2026-10-04 — https://www.postgresql.org/docs/current/textsearch-tables.html — confidence high — class: pattern
- Multi-field concatenation index: `GIN (to_tsvector('english', title || ' ' || body))` — PostgreSQL (current docs), n.d., accessed 2026-10-04 — https://www.postgresql.org/docs/current/textsearch-tables.html — confidence high — class: pattern
- Stored generated column pattern: `ADD COLUMN document tsvector GENERATED ALWAYS AS (to_tsvector('english', coalesce(title,'') || ' ' || coalesce(body,''))) STORED` + GIN index; faster queries (no per-query re-computation of to_tsvector) at the cost of extra disk; expression index is simpler and uses less disk — PostgreSQL (current docs), n.d., accessed 2026-10-04 — https://www.postgresql.org/docs/current/textsearch-tables.html — confidence high — class: pattern
- `to_tsvector` produces lexemes with positions, removes stop words, and is configurable per language; `coalesce` recommended for NULL handling — PostgreSQL (current docs), n.d., accessed 2026-10-04 — https://www.postgresql.org/docs/current/textsearch-controls.html — confidence high — class: doc
- Weighted multi-field documents: `setweight(tsvector, 'A'..'D')` combined with `||` (documented example: title=A, keywords=B, abstract=C, body=D) — PostgreSQL (current docs), n.d., accessed 2026-10-04 — https://www.postgresql.org/docs/current/textsearch-controls.html — confidence high — class: pattern
- Query parsers: `to_tsquery` (operators &,|,!,<->, prefix `*`, weights), `plainto_tsquery` (ANDs all terms), `phraseto_tsquery` (phrase), and `websearch_to_tsquery` (web-style syntax: quoted phrases, OR, `-` exclusion; never raises syntax errors — safe for raw user input) — PostgreSQL (current docs), n.d., accessed 2026-10-04 — https://www.postgresql.org/docs/current/textsearch-controls.html — confidence high — class: pattern
- Ranking: `ts_rank` and `ts_rank_cd` (cover density); default weights {D,C,B,A} = {0.1,0.2,0.4,1.0}; normalization bitmask; docs note ranking "can be expensive" and I/O-bound — PostgreSQL (current docs), n.d., accessed 2026-10-04 — https://www.postgresql.org/docs/current/textsearch-controls.html — confidence high — class: doc
- Highlighting: `ts_headline` returns a match-containing fragment; docs warn its output is not guaranteed HTML-safe (XSS caveat) — PostgreSQL (current docs), n.d., accessed 2026-10-04 — https://www.postgresql.org/docs/current/textsearch-controls.html — confidence high — class: doc
- `jsonb_to_tsvector` was NOT evidenced on the retrieved pages (likely in ch. 9.13 Text Search Functions and Operators); JSONB-specific FTS behavior remains unverified this round — Research assistant, accessed 2026-10-04 — https://www.postgresql.org/docs/current/textsearch-controls.html — confidence low — class: failure
- External-engine threshold (when Elasticsearch/OpenSearch/Typesense/Meilisearch become justified at ≤ 20k entities): no direct evidence retrieved; only indirect signals — Backstage ships a community PostgreSQL search-engine module and Lunr as an in-process option, and PG docs position GIN-indexed FTS as the standard approach — Backstage, n.d., accessed 2026-10-04 — https://backstage.io/docs/features/search/ — confidence low — class: practice
