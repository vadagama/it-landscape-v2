### Q5 — Generic declarative UI patterns

- react-jsonschema-form v6.11.0 (current per docs banner): "A simple React component capable of building HTML forms out of a JSON schema"; auto-generates a React form from JSON Schema; requires a pluggable validator (`@rjsf/validator-ajv8`); `uiSchema` and other form props exist "to customize the look and feel of the form beyond the default themes" — rjsf-team.github.io, n.d., accessed 2026-10-04 — https://rjsf-team.github.io/react-jsonschema-form/docs/ — confidence high — class: pattern
- RJSF philosophy explicitly bounds the approach: "If you want to generate a form for any data, sight unseen… react-jsonschema-form may be for you. If you have a priori knowledge of your data and want a toolkit for generating forms for it, you might look elsewhere" — schema-driven generation is positioned for unknown/evolving data (exactly a metamodel-driven catalog), at the cost of needing a second layer (uiSchema) for presentation — same URL — confidence high — class: pattern
- Inference (labeled, from the two prior bullets + Backstage Q4): production schema-driven UIs converge on two layers — JSON Schema for structure/fields + a separate presentation config (uiSchema / app-config.yaml) — rather than one schema driving everything — confidence medium — class: pattern
- NOT found this run: primary evidence for config-driven grid column definitions (AG Grid docs), JSON Forms framework docs, view DSLs, and documented failure modes of schema-driven UI for complex interactions/graphs — class: failure
