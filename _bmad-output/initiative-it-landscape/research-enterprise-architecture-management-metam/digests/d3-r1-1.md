# D3 r1 — Ardoq teardown (assistant 1, round 1)

Method note: budget spent 15 tool calls, 9 distinct sources read (8 help articles + sitemap). All evidence from official Ardoq documentation, accessed 2026-10-04.

## Questions

1. Official building blocks of the "dynamic metamodel" (components, references, fields, …)?
2. Official canonical list of default component types?
3. Reference types: definition, directionality, typing per component pair?
4. Field types, constraints; how metamodel customization works and who governs it?
5. Data model under the hood (property graph? Gremlin? versioning)?
6. ArchiMate support: out-of-the-box metamodel, import, or neither?
7. Metamodel versioning/migration when customizations change?

## Findings

**Q1 — Building blocks**
- Official building blocks: **Models** ("define the structure of workspaces, including their components, references and fields"), **Workspace** (contains components + references; holds a single model; dependencies linkable across workspaces), **Fields** ("permanent attributes … set per component and reference type(s) or globally"; searchable/filterable), **Tags**, **Components** ("represents any business object or entity"), **References** ("any relationship (as defined by your model) that links two components"), plus Attachments/Surveys/Reports — Ardoq Help, 2025-05-02, accessed 2026-10-04, https://help.ardoq.com/en/articles/44162-what-are-the-building-blocks-of-ardoq — confidence: high — class: doc
- Metamodel = "a database schema that defines the hierarchy of pages and valid relationships between the pages inside a workspace"; enables automatic visualizations and input validation; strict 1:1 metamodel↔workspace ("Every metamodel is associated with one workspace and vice versa"); Ardoq historically conflated "model" with "metamodel" in API naming — Ardoq Help, 2025-05-03, accessed 2026-10-04, https://help.ardoq.com/en/articles/44159-what-are-metamodels — confidence: high — class: doc
- "Every Workspace has a Metamodel with a certain set of component types"; names/colors/shapes/images user-editable and new component types can be added — Ardoq Help, 2026-06-05, accessed 2026-10-04, https://help.ardoq.com/en/articles/44068-manage-component-types-and-metamodel — confidence: high — class: doc

**Q2 — Default component types**
- No single official canonical list of all default component types; types ship per out-of-the-box metamodel/template. 19 out-of-the-box metamodels listed: Application Service, ArchiMate (Application/Business/Implementation & Migration/Motivation/Physical/Strategy/Technology layers), Blank Workspace, Business Process, Chapter Model, Role-Based Process, Data Flow, Enterprise Integration Model, Infrastructure, Requirements, Master Data, Microservice, Process Flow — Ardoq Help, 2025-05-03, accessed 2026-10-04, https://help.ardoq.com/en/articles/44159-what-are-metamodels — confidence: high — class: doc
- Example: "Application Portfolio" template ships exactly 4 component types (Application, Application Group, Application Module, Interface) — types are template-scoped, not one global catalog — Ardoq Help, 2026-06-05, accessed 2026-10-04, https://help.ardoq.com/en/articles/44068-manage-component-types-and-metamodel — confidence: high — class: doc

**Q3 — References**
- References are first-class data objects with explicit **source** and **target** components (directed); a component can hold multiple incoming and outgoing references — Ardoq Help, 2026-06-05, accessed 2026-10-04, https://help.ardoq.com/en/articles/44157-what-are-references — confidence: high — class: doc
- Default built-in reference type is a generic **"implicit reference"** ("two components are related in some way… doesn't make their relationship explicit"); vendor practice recommends named, reusable reference types (e.g., "Person Owns Application"); reference types reusable within the workspace where created — Ardoq Help, 2026-06-05, accessed 2026-10-04, https://help.ardoq.com/en/articles/44157-what-are-references — confidence: high — class: practice
- Reference typing constrained per component-type pair by the metamodel: "You can only connect components that have a defined relationship in your organization's metamodel"; undefined pairs show "n/a" — Ardoq Help, 2026-06-05, accessed 2026-10-04, https://help.ardoq.com/en/articles/44157-what-are-references — confidence: high — class: doc
- Parent–child hierarchy is NOT a reference: "not implemented as a reference but instead derived from hierarchy", and cannot span workspaces — Ardoq Help, 2026-06-05, accessed 2026-10-04, https://help.ardoq.com/en/articles/44157-what-are-references — confidence: high — class: doc

**Q4 — Fields & customization governance**
- Fields = metadata on components or references; metamodels come with metamodel-specific fields/references, custom ones addable; all components carry built-in fields (e.g., type, last modified); creation flow binds each field to ≥1 component type or reference type ("Applies to…"), with organization-wide field reuse — Ardoq Help, 2026-09-28 (lastmod), accessed 2026-10-04, https://help.ardoq.com/en/articles/44158-what-is-a-field — confidence: high — class: doc
- Field types: Text, Number, Email, Text paragraph, Date time, Checkbox (true/false/null), List, Select-multiple list, User, URL, Date range, Calculated field, File (SAP Signavio-only); number formatting by locale/currency; ~40 reserved field names blocked (includes `_id`, `id`, `version`, `_version`, `source`, `target`, `typeId`, `componentTypeId`, `referenceTypeId`, `rootWorkspace`, `ardoq-entity-type`, `parent`, `children`, `type`, `name`…) — Ardoq Help, 2026-09-28 (lastmod), accessed 2026-10-04, https://help.ardoq.com/en/articles/44158-what-is-a-field — confidence: high — class: doc
- Vendor guidance for metamodel design: use a field to qualify a component, but model a new component + reference when details are too rich (Operating System example) — Ardoq Help, 2026-09-28 (lastmod), accessed 2026-10-04, https://help.ardoq.com/en/articles/44158-what-is-a-field — confidence: high — class: practice
- Governance signals: autogenerated-metamodel view is admin-only and can "validate that only the allowed … references are being used" (completion rates per field/reference); Gremlin query creation is a separately granted "Create Gremlin" privilege (role- or user-level) that exposes the whole graph regardless of workspace permissions — Ardoq Help, 2025-06-06, https://help.ardoq.com/en/articles/44060-autogenerated-metamodel; Ardoq Help, 2026-06-18, https://help.ardoq.com/en/articles/44110-gremlin-graph-search, both accessed 2026-10-04 — confidence: high — class: doc

**Q5 — Data model under the hood**
- Ardoq data is a graph: users build an "Enterprise Intelligence Graph" (Digital Twin); queries use Gremlin traversal language over "vertices and edges"; component type = `label()`; example `g.V().has('name','mongodb-1').both().hasLabel('Application').dedup()` — Ardoq Help, 2026-06-18, accessed 2026-10-04, https://help.ardoq.com/en/articles/44110-gremlin-graph-search — confidence: high — class: doc
- Gremlin-reserved properties: `id()`=Ardoq OID, `component-key`=Ardoq ID, `created`, `last-updated`, `rootWorkspace`, `label()`=Type, plus created/modified-by name+email — Ardoq Help, 2026-06-18, accessed 2026-10-04, https://help.ardoq.com/en/articles/44110-gremlin-graph-search — confidence: high — class: doc
- Reserved-name list shows documents carry `version`/`_version`, `source`/`target`, `componentTypeId`/`referenceTypeId`, `rootWorkspace` — consistent with references-as-edges and per-document version fields (likely optimistic concurrency), but versioning semantics NOT documented in pages read (inference only) — Ardoq Help, 2026-09-28 (lastmod), accessed 2026-10-04, https://help.ardoq.com/en/articles/44158-what-is-a-field — confidence: low — class: doc (needs 2nd source; check REST API docs)
- A REST API exists and is a first-class write path (references creatable via REST API; checkbox reset documented as REST `PATCH` … `null`); API-dedicated docs exist — Ardoq Help, 2026-09-28 (lastmod), https://help.ardoq.com/en/articles/44158-what-is-a-field; Ardoq Help, 2026-08-28 (lastmod), https://help.ardoq.com/en/articles/44128-ardoq-rest-api, both accessed 2026-10-04 — confidence: high — class: doc

**Q6 — ArchiMate**
- "Ardoq comes with ArchiMate 3.1 templates out-of-the-box, including custom shapes, icons, and meta models"; 3.1-specific types loaded (e.g., Value Stream notation); BPMN icon set out-of-the-box; UML only partially supported — Ardoq Help, 2025-07-30, accessed 2026-10-04, https://help.ardoq.com/en/articles/44166-which-notations-are-supported — confidence: high — class: doc (capability claim ~15 months old; re-confirm current ArchiMate version)
- 7 ArchiMate layer metamodels ship as workspace metamodels — Ardoq Help, 2025-05-03, accessed 2026-10-04, https://help.ardoq.com/en/articles/44159-what-are-metamodels — confidence: high — class: doc

**Q7 — Versioning/migration**
- Changing a component-type hierarchy after workspace creation has no direct edit; documented workaround is rename → recreate as child → bulk re-type via Grid Editor → delete old type (type hierarchy effectively frozen at workspace creation) — Ardoq Help, 2026-06-05, accessed 2026-10-04, https://help.ardoq.com/en/articles/44068-manage-component-types-and-metamodel — confidence: high — class: doc
- Documented migration/refactoring surfaces exist: "Field Refactoring Instructions" (lastmod 2026-09-03), "How to Update Your Scenarios Metamodel With Your Mainline Metamodel" (lastmod 2026-08-31), "Metamodel Compliance Reports" (2026-06-06), "How to Define, Enforce, and Manage Metamodel Constraints" (lastmod 2026-07-20), "View Workspace History and Revert Changes" (lastmod 2025-12-15) — titles verified via sitemap; article bodies NOT read this run — Ardoq Help sitemap, accessed 2026-10-04, https://help.ardoq.com/sitemap.xml — confidence: medium — class: doc (needs 2nd source: read the articles)

## Not found

- **No official canonical list of default component types** anywhere in pages read — Ardoq structures default content as per-metamodel/solution templates, not one global type catalog. The 19-metamodel list is the closest official artifact.
- **No official doc on graph versioning semantics** (how `version`/`_version` behave, optimistic locking, snapshot/rollback) in pages read; "workspace history and revert" article exists but unread.
- No statement of which role may edit metamodels / create fields in pages read (admin-only status documented only for autogenerated-metamodel view and Gremlin privilege). Permissions model per asset exists (https://help.ardoq.com/en/articles/44148-assigning-users-access-to-functionality-and-assets) but unread.
- **Inverse/reference-direction semantics** (whether a reverse reference auto-created, bidirectional traversal vs. storage) not documented in pages read; Gremlin `both()` implies traversable both ways but storage direction semantics undocumented.
- **Bing, DuckDuckGo, Mojeek all blocked or empty** this run — discovery relied on the help-center sitemap, which proved sufficient; note as environment finding, not an Ardoq gap.
