# Дизайн-пакет

Эту папку ведут дизайнеры, продакты и аналитики вместе с ИИ-агентом и канвасом — [app-canvas](https://github.com/maelsmo/app-canvas). Здесь лежит всё, что уходит в разработку: макеты с готовым фронтом, прототип, спека экранов, доска с кадрами и список изменений. Программисту канвас ставить не нужно (сам канвас — приватный репозиторий, доступ — у владельца).

## Коротко

| посмотреть экраны и пройти сценарий | [prototype/index.html](prototype/index.html) — двойной щелчок, откроется в браузере |
| запустить макеты | `cd design/app && npm ci`, затем `npm run dev` (веб) или `npx expo start` (мобильное) |
| что поменялось с прошлой передачи | [CHANGES.md](CHANGES.md) |

## Что лежит в папке

| Путь | Что это |

## Прототип

`prototype/index.html` открывается двойным щелчком, прямо с диска: экраны в рамке устройства, переходы по нажатию, состояния, светлая и тёмная тема. Сервер и сеть не нужны. Кадры прототип берёт из соседней папки `board/`, поэтому переносите его вместе с `design/` целиком, а не одним файлом.

## Макеты

Макеты — настоящее приложение на том же ките, что будет в продукте, со всеми экранами из доски и данными-заглушками.

**Веб** (Vite + React + HeroUI v3):

```bash
cd design/app
npm ci
npm run dev          # адрес — в выводе; npm run build — сборка, npm run typecheck — типы
```

**Мобильное** (Expo + HeroUI Native):

```bash
cd design/app
npm ci
npx expo start       # QR-код для Expo Go на телефоне; «a» — эмулятор Android, «i» — симулятор iPhone
```

Мобильные макеты работают и без канваса: экспортёр дерева блоков, который нужен канвасу для съёмки, без него подменяется заглушкой — `CanvasRoot` просто отрисовывает приложение.

Если в `canvas.config.json` ключ `app.dir` ведёт на приложение продукта, а не на `app/`, макетов в папке нет: канвас снимает кадры с вашего приложения.

**Данные.** Экраны читают данные только через контракты — `app/contracts/` (сущности и интерфейсы экранов), а заглушки — наборы фикстур в `app/mocks/`. Чтобы подключить настоящий API, реализуйте `app/contracts/provider.ts` поверх него и подключите его вместо провайдера моков в `app/src/data/`; подробно — [specs/02-data-contracts.md](specs/02-data-contracts.md).

## Спека

- [specs/01-screens.md](specs/01-screens.md) — каждый экран: цель, что на нём, данные, действия, состояния и критерии приёмки.
- [specs/02-data-contracts.md](specs/02-data-contracts.md), [specs/03-components.md](specs/03-components.md), [specs/04-design.md](specs/04-design.md) — контракты и моки, свои компоненты поверх кита, токены и правила дизайна.
- [board/HANDOFF.md](board/HANDOFF.md) — сводка для реализации: экраны, состояния, переходы, компоненты кита с вариантами, контракты с примерами фикстур, открытые вопросы.
- [board/SCREENS.md](board/SCREENS.md) — индекс экранов: id, сценарий, как дойти, исходники, раздел спеки.
- **Компоненты проекта** — локальные файлы или папки `app/src/components/`, рабочие сценарии и ссылки на места использования. Документация API, расширенные тесты, stories и история версий нужны при отдельной подготовке публикации в общую библиотеку. Экземпляры меняют текст и настройки без правки общего источника; подключённые версии обновляются явно.

## Изменения

[CHANGES.md](CHANGES.md) — одна запись на каждую передачу, свежие сверху: сводка дизайнера, новые и изменённые экраны, состояния, переходы, контракты, свои компоненты с новыми версиями, открытые замечания и версия канваса.

## Как открыть доску

На доске — все экраны с настоящими кадрами, стрелки переходов, состояния, телефон, планшет и компьютер, обе темы, языки, замечания пинами и инспектор компонентов.

Для доски нужен доступ к приватному репозиторию канваса: попросите владельца пригласить вас в `maelsmo/app-canvas`, затем выполните `gh auth login`. Прототипу и макетам доступ не нужен.

Из корня репозитория продукта — одна строка:

```bash
git clone --filter=blob:none --sparse https://github.com/maelsmo/app-canvas.git .canvas && python3 .canvas/canvas_setup.py
```

Потом — `/canvas-board` в своём агенте или `python3 .canvas/board.py serve` в терминале. Канвас ляжет в `.canvas/` и в git не попадёт: он исключается через `.git/info/exclude`, ваш `.gitignore` не меняется. Установка ставит локально, вне git: команды канваса в ваши агенты (домашний каталог), драйвер слияния файлов доски и проверку перед коммитом (`.git/hooks/pre-commit`, если у проекта нет своего `core.hooksPath`), а для Claude Code — правила в `.claude/settings.local.json` (вопрос перед командами git, которые меняют ветку, отправляют работу или удаляют файлы, и запрет `--no-verify`). Ваши обычные коммиты она не трогает; коммит, который меняет `design/`, проходит проверки дизайн-пакета.

Вопрос дизайнерам можно задать пином на кадре: нить сохранится в `board/comments.json` — закоммитьте её в свою ветку и откройте PR, дизайнеры увидят её на доске.

## Кто правит папку

`design/` правят дизайнеры: каждая задача — ветка `design/<задача>` и запрос на слияние (PR) в основную ветку. В `main` всегда лежит последняя принятая версия макетов; «передано» — это слияние такого PR.

Канвас пишет в git продукта только `design/`: ваш код, `.gitignore`, CI, `AGENTS.md` и настройки агентов в git он не трогает. У дизайнеров локальная проверка перед коммитом на ветке `design/*` не пропускает файлы вне этой папки.

Правка в `design/` из вашей ветки (например, в контракте) — лучше отдельным PR, и предупредите дизайнеров.

## Слияние без канваса

У дизайнеров файлы доски `board/*.json` сливает канвас — по id экранов, переходов и замечаний. У вас канваса может не быть, и тогда git сливает эти файлы построчно, как обычный текст; так же делает кнопка слияния на GitHub. Конфликт в `design/board/*.json` руками не чините: попросите дизайнера слить ветки у себя — канвас разберёт доску по id и не потеряет замечания.
